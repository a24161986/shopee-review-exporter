# 当前窗口商品导出设计

## 目标

把扩展的主流程从“扫描当前页面内容”改成“识别当前 Chrome 窗口里已经打开的 Shopee 商品详情标签页，然后批量导出评论”。

目标用户流程：

1. 用户打开多个 Shopee 商品详情页，可能来自不同国家站点。
2. 用户打开扩展弹窗。
3. 用户设置导出格式、每个商品评论条数、评论筛选。
4. 用户点击 `识别当前窗口商品页`。
5. 扩展只读取当前窗口各个标签页地址栏里的 URL，并列出商品详情页。
6. 用户点击 `开始导出`。
7. 扩展逐个商品导出文件，并显示每个商品成功或失败。
8. 如果还有失败项，用户点击 `重试失败项`，只重新导出失败商品。

## 术语

- `popup`：程序员语境里指 Chrome 扩展点击工具栏图标后打开的小窗口；在本项目里就是设置导出选项、导入商品、开始导出和重试失败项的面板。
- `tab`：程序员语境里指浏览器里的一个标签页；在本项目里只处理当前 Chrome 窗口中的标签页。
- `URL`：程序员语境里指网页地址；在本项目里只读取浏览器地址栏里的链接，不读取网页内容里的链接。
- `task`：程序员语境里指一个待执行任务；在本项目里一个有效 Shopee 商品就是一个导出任务，并生成一个文件。
- `queue`：程序员语境里指排队等待执行的一组任务；在本项目里导出队列一次只处理一个商品，降低被 Shopee 限制的概率。
- `dedupe`：程序员语境里指去重；在本项目里按 `domain + shopId + itemId` 判断同一个商品。
- `domain`：程序员语境里指网站域名；在本项目里是 `shopee.vn`、`shopee.sg`、`shopee.com.my` 这类国家站点。

## 主来源：当前窗口标签页

主按钮改为 `识别当前窗口商品页`。

点击后，弹窗执行：

1. 通过 Chrome tabs API 读取当前窗口的所有标签页。
2. 只读取每个标签页的 `url` 字段。
3. 解析支持的 Shopee 商品详情 URL。
4. 忽略所有非商品 URL：
   - 搜索页。
   - 类目页。
   - 文章页。
   - 购物车、订单、登录等其他 Shopee 页面。
   - 非 Shopee 页面。
5. 按 `domain + shopId + itemId` 去重。
6. 把有效商品加入任务列表，来源显示为 `标签页`。

这里的 Chrome tabs API 指 Chrome 扩展提供的标签页读取能力；在本项目里用它读取当前窗口标签栏中的 URL。

主流程不能读取页面 DOM、`<a>` 标签、页面文本、推荐商品、面包屑类目或网页里嵌入的链接。DOM 是网页结构树；在本项目里明确不把 DOM 当作商品发现来源。

支持的商品 URL 格式保持为：

- 点号商品格式：`https://shopee.<site>/<slug>-i.<shopId>.<itemId>`
- 路径商品格式：`https://shopee.<site>/product/<shopId>/<itemId>`

类似 `cat.11027421.11027457` 的类目 URL 不能被当作商品。

## 辅助来源：粘贴链接

弹窗增加 `粘贴商品链接` 区域。

行为：

1. 用户可以一行一个链接，也可以粘贴一整段混合文本。
2. 用户点击 `导入链接`。
3. 扩展从文本中提取 Shopee URL。
4. 只有有效 Shopee 商品详情 URL 会变成任务。
5. 无效文本、搜索页、类目页、非 Shopee URL 会被忽略，不进入任务列表。
6. 导入商品会和现有标签页商品去重。
7. 弹窗显示一条简短导入结果，例如：`已导入 12 个商品，忽略 3 条无效内容`。

来源显示：

- 从当前窗口标签页识别到的商品显示 `标签页`。
- 从粘贴内容导入的商品显示 `粘贴`。
- 同一个商品同时来自标签页和粘贴内容时，显示 `标签页/粘贴`。

## 移除来源：当前页面内容

旧的 `扫描当前页` 功能从 UI 中移除。

扩展不再提供“扫描当前网页里有哪些商品链接”的功能。这样可以避免把推荐商品、面包屑类目、页面广告、相关文章里的链接误加入任务列表。

## 任务状态

任务列表只保留四种状态：

- `等待`：商品已经进入任务列表，但还没有开始导出。
- `导出中`：当前正在处理这个商品。
- `成功`：已经按要求生成文件。
- `失败`：这次没有导出成功，可以重试。

无效链接不作为任务状态显示。粘贴导入里的无效内容只在导入结果中计数，不进入任务列表。

不再把 `已停止` 作为最终任务状态。用户点击停止后，任务列表保持可继续理解：

- 已完成任务保持 `成功`。
- 已失败任务保持 `失败`。
- 尚未运行任务回到 `等待`。
- 正在中断的任务如果已经开始请求评论，标为 `失败` 并显示简短中断原因；如果还没真正开始请求，回到 `等待`。

## 导出与重试

导出仍然是每个商品一个文件。

后台队列继续保持一次只处理一个商品：

1. 打开一个非激活商品标签页。
2. 按设置拉取评论，直到达到目标条数或没有更多评论。
3. 归一化评论数据，并按时间从新到旧排序。
4. 下载一个 JSON 或 Excel 文件。
5. 继续下一个商品。

这里 `归一化` 的通用意思是把不同来源的数据整理成统一字段；在本项目里就是把 Shopee 评论接口返回值整理成固定导出列。

重试行为：

1. 只要存在 `失败` 任务，就显示 `重试失败项`。
2. 点击后只重新运行失败任务。
3. 成功任务保持 `成功`。
4. 重试任务从 `失败` 变成 `等待`，再变成 `导出中`，最后变成 `成功` 或 `失败`。
5. 如果重试后仍有失败，`重试失败项` 继续可用。

重试使用该任务上一次开始导出时保存的设置，包括格式、评论条数和评论筛选。这样用户点击重试时，不会因为改动了弹窗设置而无意改变失败项的导出要求。

## 汇总显示

弹窗汇总保持简单：

```text
总数：N · 成功：A · 失败：B
```

识别或导入时可显示：

```text
识别到 N 个商品
已导入 A 个商品，忽略 B 条无效内容
```

## UI 布局

弹窗保持紧凑工具型布局：

1. 标题：`Shopee 评论导出`。
2. 主按钮：`识别当前窗口商品页`。
3. 设置区：
   - 导出格式。
   - 每个商品评论条数。
   - 评论筛选。
4. 粘贴链接区：
   - 文本框。
   - `导入链接`。
   - 可选 `清空输入`。
5. 导出控制：
   - `开始导出`。
   - `暂停`。
   - `停止`。
   - 有失败项时显示 `重试失败项`。
6. 汇总和任务列表。

弹窗内不放长篇说明文字，只保留短标签和明确按钮。

## 错误处理

单个商品失败不能阻塞后续商品。

失败任务显示简短原因，例如：

- `商品页加载超时`
- `HTTP 403`
- `评论接口没有返回数据`
- `下载失败`

`HTTP 403` 是服务器拒绝访问的状态码；在本项目里通常表示 Shopee 暂时不允许这次评论请求继续。

导出结束后任务列表保留，方便用户查看失败项并重试。

## 权限

现有扩展权限可以支持这个流程：

- `tabs`：读取当前窗口标签页 URL，并为导出打开非激活商品标签页。
- `scripting`：在商品页里执行评论请求代码。
- `downloads`：保存导出的 JSON 或 Excel 文件。
- `storage`：保存设置和队列状态。
- `alarms`：配合 Manifest V3 后台生命周期恢复队列。

Manifest V3 是 Chrome 扩展当前的配置/运行规范；在本项目里它决定后台脚本以 service worker 形式运行。service worker 是浏览器按需唤醒的后台脚本，在本项目里负责导出队列。

`activeTab` 不再是主扫描流程的核心权限，因为主流程不注入当前页面，只读取当前窗口标签 URL。

## 测试策略

增加或更新测试：

- 解析多个国家站点的真实 Shopee 商品 URL。
- 拒绝 Shopee 类目页、搜索页和其他非商品 URL。
- 从当前窗口标签页 URL 列表构建商品任务。
- 标签页来源和粘贴来源之间去重。
- 重复商品合并来源标签。
- 从混合粘贴文本中导入有效商品并统计无效内容。
- 只重试失败任务。
- 任务状态只允许 `等待`、`导出中`、`成功`、`失败`。

手动验证：

- 在 Chrome 中加载未打包扩展。
- 在同一个 Chrome 窗口打开三个不同国家的 Shopee 商品页。
- 点击 `识别当前窗口商品页`，确认只出现这些商品标签页。
- 确认搜索页、类目页、非 Shopee 标签页被忽略。
- 用小评论条数导出 JSON，确认每个商品一个文件。
- 制造或观察失败项，然后点击 `重试失败项`。
- 粘贴一段混合文本，包含有效商品 URL、类目 URL、普通文本，确认只有商品 URL 进入任务列表。

## 非目标

- 不扫描当前网页内部链接。
- 不扫描所有 Chrome 窗口。
- 不读取页面 DOM 来发现商品链接。
- 不把无效粘贴内容当作任务。
- 不并发导出多个商品。
- 不把多个商品合并到一个输出文件。
